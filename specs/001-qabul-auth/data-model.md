# Data Model: Authentication

## User

Represents an authenticated actor in the system.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | UUID v7 | Yes | Primary key generated by Hibernate UUID v7 support |
| `phone_number` | varchar(20) or numeric string | Applicant only | Unique when present; used for applicant registration/login |
| `username` | varchar(100) | Staff only | Unique when present; used for admin/moderator login |
| `password_hash` | varchar | Yes after verification | bcrypt hash only; raw passwords are never stored |
| `type` | enum `ADMIN`, `MODERATOR`, `APPLICANT` | Yes | JWT `role` claim is derived from this value |
| `language` | enum `UZ`, `RU`, `EN` | No | Defaults to `UZ` when omitted |
| `created_at` | timestamp | Yes | Set on insert |
| `updated_at` | timestamp | Yes | Set on update |

### Validation Rules

- Applicant users must have `phone_number` and must not require `username`.
- Staff users must have `username` and may omit `phone_number`.
- `phone_number` and `username` are separate identifier spaces.
- `password_hash` must be produced by bcrypt.
- Admin startup upsert must find the admin by configured username and update the password hash if credentials changed.

### Relationships

- One `User` has many `Session` records.
- One applicant `User` may be created from a verified `OtpChallenge`.

## OtpChallenge

Tracks applicant first-time registration verification.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | UUID v7 | Yes | Primary key |
| `phone_number` | varchar(20) | Yes | Applicant phone under verification |
| `otp_hash` | varchar | Yes | Hash of the 6-digit OTP or equivalent one-way representation |
| `status` | enum `ACTIVE`, `VERIFIED`, `EXPIRED`, `REPLACED` | Yes | Latest request for a phone is the only active challenge |
| `expires_at` | timestamp | Yes | Default expiry is 5 minutes after issue |
| `verified_at` | timestamp | No | Set when OTP is accepted |
| `created_at` | timestamp | Yes | Set on insert |
| `updated_at` | timestamp | Yes | Set on update |

### Validation Rules

- OTP value must be 6 digits.
- Only one `ACTIVE` challenge may exist for a phone number.
- Requesting a new OTP for the same phone marks previous active challenges `REPLACED`.
- Expired or non-active challenges cannot complete registration.
- Local development prints the generated OTP to application console; production delivery remains out of scope.

### State Transitions

```text
ACTIVE -> VERIFIED
ACTIVE -> EXPIRED
ACTIVE -> REPLACED
```

## Session

Tracks refresh-token sessions and pending verification state.

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | UUID v7 | Yes | Primary key |
| `user_id` | UUID v7 | Yes | Foreign key to `users.id` |
| `token` | text | Yes | Refresh token value or refresh token hash, depending on implementation task decision |
| `status` | enum `ACTIVE`, `PENDING_VERIFICATION` | Yes | Required by spec |
| `user_agent` | varchar | No | Captured from request header |
| `expired_at` | timestamp | Yes | Refresh session expiry |
| `created_at` | timestamp | Yes | Set on insert |
| `updated_at` | timestamp | Yes | Set on update |

### Validation Rules

- `ACTIVE` sessions may issue new access tokens until `expired_at`.
- Expired sessions must be rejected during refresh.
- `PENDING_VERIFICATION` may be used only before first-time applicant password completion.
- Token records should support later revocation without changing the public contract.

### State Transitions

```text
PENDING_VERIFICATION -> ACTIVE
ACTIVE -> expired by time
```

## Auth DTOs

### ApplicantPhoneRequest

- `phone_number`: required phone value.

### VerifyOtpRequest

- `phone_number`: required phone value.
- `otp`: required 6-digit string.

### SetPasswordRequest

- `verification_token`: required short-lived token or verification identifier from OTP success.
- `password`: required password satisfying configured password policy.

### ApplicantLoginRequest

- `phone_number`: required registered applicant phone.
- `password`: required raw password for verification only.

### StaffLoginRequest

- `username`: required staff username.
- `password`: required raw password for verification only.

### RefreshTokenRequest

- `refresh_token`: required refresh JWT.

### TokenResponse

- `access_token`
- `refresh_token`
- `token_type`: `Bearer`
- `expires_in`
- `refresh_expires_in`
- `user_id`
- `role`

### ErrorResponse

- `code`
- `message`
- `details`
- `timestamp`
